# Методологія розробки: V-модель

Обрано **V-модель** (розширення каскадної моделі, у якій кожному етапу проєктування відповідає
рівень тестування). Підстави:

1. Вимоги стабільні й повністю задані методичкою та варіантом — ітеративне уточнення з замовником (Agile) не потрібне.
2. Результат математично перевірюваний: для кожного рівня проєктування можна заздалегідь сформулювати критерії перевірки
   (вузли інтерполяції, ортогональність залишків, межі осей тощо).
3. Обсяг невеликий, ризики низькі — спіральна модель з аналізом ризиків надлишкова.

| V1. Вимоги (ТЗ) | `docs/TZ.md` | V7. Приймальне тестування | `docs/analysis.md`, скріншоти, таблиця «вимога → тест» |
